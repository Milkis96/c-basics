디버거프로그램을 일시정지하고 한 줄씩 보는 돋보기

프로그램은 눈 깜짝할 새에 끝나서 중간에 무슨 일이 있었는지 볼 수 없어요. 디버거는 원하는 줄에서 멈추고, 한 줄씩 넘기면서 변수 안을 들여다보게 해 줘요.

1디버거란?

디버거는 프로그램을 멈춰 놓고 안을 들여다보는 도구예요.버그(bug, 벌레)를 잡는(de-) 도구라서 디버거예요.

영상의 일시정지 버튼과 비슷해요. 원하는 장면(줄)에서 멈추고, 한 프레임(한 줄)씩 넘기면서, 그 순간 변수에 무슨 값이 있는지 확인해요.

  • 중단점: "여기서 멈춰!" 표시. 코드 왼쪽에 빨간 동그라미로 보여요.
  • 한 줄 실행: 멈춘 상태에서 다음 줄만 실행해요. 노란 화살표가 지금 실행할 줄이에요.
  • 변수 보기: 지역 창, 조사식 창, 마우스를 변수 위에 올리기.

2왜 필요해?

디버거 없이

printf를 여기저기 넣고, 다시 빌드하고, 출력 보고, 또 지우고... 질문하려 해도 "그냥 안 돼요"밖에 말할 게 없어요.

디버거로

"반복문 3바퀴째에 sum이 6이어야 하는데 3이에요"처럼 어디서 무엇이 틀렸는지 정확히 말할 수 있어요.

질문할 내용을 모르겠다면, 디버거로 내가 예상한 값과 실제 값이 처음 달라지는 줄을 찾으면 돼요. 그 줄이 질문거리예요.

3쓰는 법

순서

디버깅 4단계

단계할 일키
1의심 가는 줄 왼쪽 회색 여백을 클릭해 중단점을 찍어요F9
2디버깅 시작. 중단점에서 멈추고 노란 화살표가 나타나요F5
3한 줄씩 넘기며 지역 창의 값을 지켜봐요. 바뀐 값은 빨간색이에요F10
4예상과 다른 값이 나온 줄을 찾으면 멈추고 코드를 고쳐요Shift+F5

F5와 Ctrl+F5는 달라요

F5는 디버깅하며 실행이라 중단점에서 멈춰요. Ctrl+F5는 디버깅 없이 실행이라 중단점을 무시해요. 멈추지 않는다면 이것부터 확인하세요.

4단축키와 창

키이름하는 일
F9중단점 설정/해제지금 줄에 멈춤 표시를 찍거나 지워요
F5디버깅 시작 / 계속다음 중단점까지 쭉 실행해요
F10프로시저 단위 실행한 줄 실행. 함수가 있어도 들어가지 않고 결과만 받아요
F11한 단계씩 코드 실행한 줄 실행. 함수가 있으면 그 안으로 들어가요
Shift+F11프로시저 나가기지금 함수를 끝까지 실행하고 부른 곳으로 돌아가요
Shift+F5디버깅 중지프로그램을 끝내요

값을 보는 창 (디버깅 중 메뉴: 디버그 → 창)

지역 (Locals)지금 함수의 변수가 자동으로 다 보여요. 가장 먼저 볼 창.
조사식 (Watch)보고 싶은 것을 직접 적어요. sum / 2, arr[i]처럼 식도 돼요.
호출 스택지금 어느 함수 안에 있고, 누가 불렀는지 보여요.

창을 열기 귀찮으면 코드의 변수 위에 마우스를 올리기만 해도 값이 떠요.

6문제 풀기

1번키 고르기

중단점을 찍었는데 F5 대신 Ctrl+F5를 눌렀어요. 어떻게 될까요?

정답 보기

멈추지 않고 끝까지 실행돼요. Ctrl+F5는 디버깅 없이 실행이라 중단점을 무시해요.

2번키 고르기
int total = add(3, 4);   // ← 노란 화살표가 여기
printf("%d", total);

add 함수 안이 잘 돌아가는지 보고 싶어요. F10과 F11 중 무엇을 눌러야 할까요?

정답 보기

F11이에요. F10은 add를 한 번에 실행하고 다음 줄로 넘어가요.

많이 틀리는 답: F10
3번상황 판단

노란 화살표가 sum += i; 줄에 있어요. 지역 창의 sum 값은 이 줄을 실행하기 전일까요, 후일까요?

정답 보기

전이에요. 노란 화살표는 "다음에 실행할 줄"이에요. F10을 한 번 더 눌러야 sum이 바뀌어요.

많이 틀리는 답: 후
4번버그 찾기
int arr[3] = { 5, 8, 2 };
int max = 0;
for (int i = 1; i < 3; i++) {
    if (arr[i] > max) max = arr[i];
}
printf("%d", max);   // 8이 나오지만 i가 0일 때를 확인 못 함

지금은 우연히 맞지만 { 9, 8, 2 }이면 틀려요. 조사식에 무엇을 넣고 보면 버그가 잘 보일까요?

정답 보기

i와 arr[i]를 조사식에 넣고 F10으로 넘겨 보면, i가 1부터 시작해서 arr[0]을 한 번도 안 본다는 걸 알 수 있어요. int i = 0으로 고쳐요.

5번도전

반복문이 1000바퀴 도는데 700번째 바퀴에서만 문제가 생겨요. F10을 700번 누르지 않고 거기서 멈추려면?

정답 보기

조건부 중단점을 써요. 빨간 동그라미를 오른쪽 클릭 → 조건 → i == 700을 적으면 그때만 멈춰요.

7이럴 땐?

중단점을 찍었는데 안 멈춰요빨간 동그라미가 속이 빈 동그라미로 바뀌어 있음
왜?Ctrl+F5로 실행했거나, 위쪽 구성이 Release로 되어 있거나, 그 줄까지 실행이 안 갔어요.
어떻게?위쪽 도구 모음에서 Debug를 고르고 F5로 실행해요. 그래도 안 멈추면 그 줄이 정말 실행되는지 더 위에 중단점을 찍어 봐요.
F10, F11을 눌러도 반응이 없거나 화면 밝기가 바뀌어요노트북 키보드
왜?노트북에서는 F키가 밝기·소리 키로 먼저 동작하는 경우가 많아요.
어떻게?Fn을 같이 누르거나, Fn Lock을 켜요. 메뉴의 디버그 → 프로시저 단위 실행으로도 할 수 있어요.
변수 값이 -858993460 같은 이상한 숫자예요지역 창: sum -858993460 int
왜?아직 초기화되지 않은 변수예요. Debug 모드에서는 빈 칸을 0xCCCCCCCC로 채워 두는데, 이걸 int로 읽으면 그 숫자예요.
어떻게?그 줄을 아직 안 지나왔다면 정상이에요. 지나왔는데도 그렇다면 초기화를 빼먹은 거예요. int sum = 0;
디버깅 중에 코드를 고쳤더니 경고 창이 떠요편집하며 계속하기 관련 안내 / 변경 내용을 적용할 수 없습니다
왜?실행 중인 프로그램에 바뀐 코드를 바로 넣지 못하는 경우가 있어요.
어떻게?Shift+F5로 멈추고, 고치고, 다시 F5로 시작해요.
F11을 눌렀더니 처음 보는 printf 코드 안으로 들어갔어요stdio.h / printf.c 같은 파일이 열림
왜?F11은 내가 만들지 않은 함수(printf, scanf_s) 안으로도 들어갈 수 있어요.
어떻게?Shift+F11로 빠져나와요. 내 함수가 아닌 줄에서는 F10을 써요.

메뉴 이름과 문구는 Visual Studio 한국어판 기준이에요. 버전에 따라 조금 다를 수 있어요.
