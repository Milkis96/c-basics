링크드 리스트다음 상자의 주소를 들고 있는 상자들의 줄

배열은 칸들이 딱 붙어 있는 기차예요. 링크드 리스트는 상자들이 메모리 여기저기 흩어져 있고, 각 상자가 "다음 상자는 몇 번지" 쪽지를 들고 있어요. 쪽지를 따라가면 줄을 끝까지 방문할 수 있어요.

이 페이지는 미션형 실습이에요. 정답 코드는 없어요. 미션을 하나 끝낼 때마다 강사에게 검사를 받고 다음 미션으로 넘어가요. 막히면 힌트를 하나씩 펼쳐 보세요.

1링크드 리스트란?

값과 "다음 상자의 주소"를 함께 담은 상자(노드)를 줄줄이 연결한 것이에요.link = 연결, list = 목록. 연결된 목록.
  • 노드(node): 상자 하나. 값(data)과 다음 노드의 주소(next)가 들어 있어요.
  • head: 첫 번째 노드의 주소를 적은 쪽지. 이걸 잃어버리면 줄 전체를 잃어버려요.
  • NULL: 마지막 노드의 next. "뒤에 아무도 없음" 표시예요.

지금까지 배운 구조체 + 포인터 + 함수 + Call by reference를 모두 쓰는 종합 실습이에요. 막히면 그 주제 페이지로 돌아가서 다시 보고 오세요.

2왜 필요해?

배열이 불편할 때

칸 수를 처음에 정해야 해요. 중간에 하나 끼우려면 뒤의 값을 전부 한 칸씩 밀어야 해요.

링크드 리스트는

필요할 때마다 상자를 하나씩 만들어요. 끼울 때는 쪽지 몇 장만 고쳐 쓰면 돼요.

게임에서화면에 생겼다 사라지는 총알, 적, 아이템 목록처럼 개수가 계속 바뀌는 것.
대신 느린 점arr[50]처럼 바로 갈 수 없어요. head부터 쪽지를 50번 따라가야 해요.

3새 문법

미션에 필요한 도구 세 가지를 짧게 다시 볼게요. 자세한 설명은 동적 할당 페이지에 있어요. 예시는 일부러 링크드 리스트가 아닌 걸로 보여 줄게요.

빌리기

malloc: 메모리를 필요할 때 빌리기

#include <stdlib.h>      // malloc, free

int *p = (int *)malloc(sizeof(int));   // int 하나 크기만큼 빌리고 주소를 받아요
if (p == NULL) return 1;               // 못 빌렸으면 멈추기
*p = 42;
  • 보통 변수는 함수가 끝나면 사라지지만, malloc으로 빌린 메모리는 free 할 때까지 남아 있어요.
  • 앞의 (int *)는 .cpp 파일에서 필요해요. 붙여 두면 .c, .cpp 둘 다 돼요.
돌려주기

free: 다 쓴 메모리 반납

free(p);       // 빌린 곳 반납
p = NULL;      // 반납한 주소를 다시 쓰지 않게 지워 두기

반납하지 않으면 메모리 누수, 반납한 뒤에 또 쓰면 프로그램이 멈추거나 이상한 값이 나와요.

화살표

-> : 포인터로 구조체 칸 쓰기

typedef struct { int hp; int atk; } Monster;

Monster *m = (Monster *)malloc(sizeof(Monster));
m->hp = 100;     // (*m).hp = 100; 과 같아요
m->atk = 7;
free(m);

자기와 같은 구조체를 가리키는 칸

노드는 "다음 노드의 주소"를 가져야 해요. 그래서 구조체 안에 자기 자신과 같은 구조체를 가리키는 포인터가 들어가요. 이때 typedef 이름은 아직 완성되지 않아서, 구조체 안에서는 struct 이름으로 불러야 해요. 미션 1에서 직접 만들어 보세요.

  3. 똑같이 나오면 손을 들고 강사에게 검사를 받아요. 강사는 실행 결과와 함께 검사 질문을 해요. 코드를 말로 설명할 수 있어야 통과예요.
  4. 통과하면 아래 표에 확인을 받고 다음 미션으로 가요.

5눈으로 보기

코드를 쓰기 전에 버튼으로 노드를 붙이고 떼어 보세요. 아래에 쪽지를 어떤 순서로 고쳐 쓰는지 말로 나와요. 이 순서를 코드로 옮기는 게 미션이에요.

    6미션

    미션 1노드 구조체

    int 값 하나와 다음 노드의 주소를 담는 구조체 Node를 만드세요. Node라는 이름으로 쓸 수 있게 typedef도 해 주세요.

    확인용 main

    int main(void) {
    Node a;
    a.data = 10;
    a.next = NULL;
    printf("%d %d\n", a.data, a.next == NULL);
    return 0;
}

    기대 출력: 10 1

    힌트 1

    칸은 두 개예요. 이름은 확인용 main을 보면 알 수 있어요.

    힌트 2

    next 칸의 자료형은 "노드를 가리키는 포인터"예요. 구조체 안에서는 아직 typedef 이름 Node를 쓸 수 없어서 struct 태그이름 *으로 써야 해요. 그러려면 typedef struct 태그이름 { ... } Node;처럼 태그 이름을 붙여야 해요.

    검사 받기

    • 확인용 main이 그대로 컴파일되고 10 1이 나온다
    검사 질문: next의 자료형이 왜 int *가 아닌가요?
    미션 2손으로 연결하기

    함수 없이 main 안에서 malloc으로 노드 2개(10, 20)를 만들고, head → 10 → 20 → NULL이 되게 연결하세요. 그다음 head만 써서 두 값을 출력하고, 두 노드를 free 하세요.

    규칙: 출력할 때는 head에서 출발해야 해요. 노드를 만들 때 쓴 변수 이름으로 바로 출력하면 안 돼요.

    기대 출력: 10 20

    힌트 1

    노드 하나를 만드는 순서: malloc → data 넣기 → next에 NULL 넣기. 두 번 반복해요.

    힌트 2

    연결은 쪽지 두 장이에요. 첫 노드의 next에 두 번째 노드의 주소, head에 첫 노드의 주소.

    힌트 3

    두 번째 값은 head에서 화살표를 두 번 따라가면 나와요. head->???->???

    검사 받기

    • 10 20이 출력된다
    • 출력이 head에서 출발한다
    • free가 2번 있다
    검사 질문: 디버거로 두 노드의 주소를 보여 주세요. 두 주소는 붙어 있나요? 배열과 무엇이 다른가요?
    미션 3printList

    head를 받아서 리스트 전체를 10 -> 20 -> NULL 모양으로 출력하는 함수 void printList(Node *head)를 만드세요. 노드가 몇 개든, 0개여도 동작해야 해요.

    확인용 main (미션 2의 연결 코드 뒤에 붙이기)

    printList(head);    // 10 -> 20 -> NULL
printList(NULL);    // NULL
    힌트 1

    "쪽지를 따라 한 칸 이동"을 NULL을 만날 때까지 반복해요. 반복 횟수를 모르니 for보다 while이 편해요.

    힌트 2

    지금 보고 있는 노드를 담는 포인터를 하나 만들어요(예: cur). 출력하고 → cur를 다음 노드로 바꾸고 → 반복.

    검사 받기

    • 두 줄 모두 기대 출력과 같다
    • 노드를 3개로 늘려도 코드를 안 고치고 동작한다
    검사 질문: 함수 안에서 head를 직접 옮겨도 main의 head는 안전한가요? 왜 그런가요? (Call by value)
    미션 4pushFront

    맨 앞에 새 노드를 추가하는 함수를 만드세요. 이번부터는 malloc을 main이 아니라 함수 안에서 해요.

    void pushFront(Node **head, int value);   // 이 모양 그대로

    확인용 main

    int main(void) {
    Node *head = NULL;
    pushFront(&head, 1);
    pushFront(&head, 2);
    pushFront(&head, 3);
    printList(head);
    return 0;
}

    기대 출력: 3 -> 2 -> 1 -> NULL

    힌트 1

    5번 "눈으로 보기"에서 맨 앞에 추가를 눌러 보세요. 쪽지를 고치는 순서가 나와요. 그 순서를 지키지 않으면 원래 줄을 잃어버려요.

    힌트 2

    함수가 바꿔야 하는 것은 main의 head 변수예요. head는 포인터니까, 그 포인터의 주소를 받아야 해요. 그래서 별이 두 개예요. 함수 안에서 *head는 main의 head 그 자체예요.

    검사 받기

    • 기대 출력과 같다
    • 빈 리스트(head가 NULL)에서 첫 추가가 된다
    검사 질문: 매개변수를 Node *head(별 하나)로 하면 어떻게 되나요? 쪽지 고치는 두 줄의 순서를 바꾸면 어떻게 되나요?
    미션 5popFront + 전부 반납

    맨 앞 노드를 빼고 free 하는 void popFront(Node **head)를 만드세요. 리스트가 비어 있으면 아무것도 하지 않아야 해요. 그리고 main 끝에서 popFront를 반복해 모든 노드를 반납하세요.

    확인용 main (미션 4의 main에 이어서)

    popFront(&head);
printList(head);     // 2 -> 1 -> NULL
// 여기에 "전부 반납" 반복문
printList(head);     // NULL
popFront(&head);     // 빈 리스트: 아무 일도 없어야 해요
    힌트 1

    free 한 노드는 다시 열어 볼 수 없어요. 그런데 head를 옮기려면 그 노드의 next가 필요해요. 그러면 무엇을 먼저 해야 할까요?

    힌트 2

    지울 노드의 주소를 다른 포인터에 잠깐 맡겨 두고 → head를 옮기고 → 맡겨 둔 걸 free.

    힌트 3

    전부 반납: "head가 NULL이 아닌 동안 popFront"를 반복해요.

    검사 받기

    • 세 줄의 기대 출력이 맞고, 마지막 popFront에서 멈추지 않는다
    • malloc 수와 free 수가 같다
    검사 질문: free를 head 옮기기보다 먼저 하면 무슨 일이 생기나요? 디버거로 보여 줄 수 있나요?
    미션 6도전

    두 함수를 더 만드세요.

    int count(Node *head);                    // 노드 개수
void pushBack(Node **head, int value);    // 맨 뒤에 추가

    확인용 main

    Node *head = NULL;
pushBack(&head, 1);
pushBack(&head, 2);
pushFront(&head, 0);
printList(head);              // 0 -> 1 -> 2 -> NULL
printf("%d\n", count(head));  // 3
    힌트 1

    count는 printList와 거의 같아요. 출력 대신 숫자를 셉니다.

    힌트 2

    pushBack은 "마지막 노드"를 찾아야 해요. 마지막 노드는 next가 NULL인 노드예요. 그리고 리스트가 비어 있을 때는 마지막 노드가 없으니 따로 처리해야 해요.

    검사 받기

    • 기대 출력과 같다
    • 빈 리스트에서 pushBack이 된다
    검사 질문: 노드가 1000개일 때 pushFront와 pushBack 중 무엇이 더 느린가요? 왜 그런가요?

    7이럴 땐?

    구조체 안의 next 줄에서 에러가 나요error C2061: 구문 오류: 식별자 'Node' · 또는 C2143
    왜?typedef 이름 Node는 구조체 정의가 끝나야 생겨요. 구조체 안에서는 아직 모르는 이름이에요.
    어떻게?3번 "새 문법"의 마지막 상자와 미션 1의 힌트 2를 다시 보세요.
    malloc 줄에서 변환할 수 없다고 나와요error C2440: '초기화 중': 'void *'에서 'Node *'(으)로 변환할 수 없습니다.
    왜?파일이 .cpp라서 C++ 규칙을 따라요.
    어떻게?malloc 앞에 (Node *)를 붙여요.
    malloc 아래에 초록 물결 경고가 생겨요C6011: NULL 포인터 'n'을(를) 역참조하고 있습니다.
    왜?malloc은 실패하면 NULL을 돌려줘요. 확인 없이 쓰면 위험하다는 경고예요.
    어떻게?쓰기 전에 NULL인지 확인하는 if를 넣어요.
    printList가 끝나지 않거나 실행 중 멈춰요예외 발생: 읽기 액세스 위반입니다. cur이(가) 0xCDCDCDCD였습니다.
    왜?어떤 노드의 next에 NULL을 안 넣었어요. Debug 모드에서 malloc한 빈 칸은 0xCD로 채워져 있어서, 그 주소로 가려다 멈춰요.
    어떻게?노드를 만들자마자 next를 정해 주고 있는지 확인해요.
    같은 값이 끝없이 출력돼요3 -> 3 -> 3 -> 3 -> ...
    왜?노드의 next가 자기 자신을 가리켜요. pushFront에서 쪽지 고치는 순서가 바뀌었을 때 생겨요.
    어떻게?5번 "눈으로 보기"의 순서와 내 코드의 순서를 한 줄씩 비교해요.
    함수 안에서 추가했는데 main의 리스트는 비어 있어요printList(head) → NULL
    왜?head를 값으로 넘겨서 함수 안의 복사본만 바뀌었어요. Call by value 페이지의 swap과 같은 문제예요.
    어떻게?매개변수가 미션의 모양(Node **head)과 같은지, 부를 때 &를 붙였는지 확인해요.
    지운 뒤에 이상한 큰 음수가 나오거나 멈춰요-572662307 (0xDDDDDDDD)
    왜?free 한 노드를 다시 읽었어요. Debug 모드에서 free된 칸은 0xDD로 채워져요.
    어떻게?미션 5의 힌트 1을 보세요. free는 항상 그 노드를 다 쓴 다음에.
