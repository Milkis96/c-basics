코딩 문제 풀이배운 걸 처음부터 혼자 써 보기

조건문, 반복문, 배열로 작은 게임 기능 5개를 만들어요. 빈 파일에서 시작해서 #include부터 직접 써요.

정답 코드는 없어요. 한 문제를 끝내면 강사에게 검사를 받고 다음 문제로 넘어가요. 막히면 힌트를 하나씩 펼치고, 그래도 막히면 해당 주제 페이지로 돌아가 보세요.

0진행 방법

  1. 문제를 읽고 입력 예시를 넣었을 때 출력 예시와 똑같이 나오게 만들어요. 띄어쓰기와 줄바꿈까지 맞춰요.
  2. 예시가 2개면 둘 다 넣어 봐요. 두 번째 예시는 보통 실수하기 쉬운 경우예요.
  3. 다 되면 손을 들고 검사를 받아요. 강사가 다른 값도 넣어 보고, 검사 질문을 해요. 코드를 말로 설명할 수 있어야 통과예요.
  4. 빨리 끝낸 사람은 각 문제의 더 해 보기까지 도전해요.

1데미지 계산조건문

공격력, 방어력, 크리티컬 여부를 입력받아 최종 데미지를 출력하세요.

  • 기본 데미지 = 공격력 - 방어력
  • 기본 데미지가 1보다 작으면 1로 해요. (최소 데미지)
  • 크리티컬이 1이면 위에서 구한 데미지를 2배로 해요. 0이면 그대로예요.
입력 예시 1
공격력: 30
방어력: 12
크리티컬(1/0): 1
출력 예시 1
데미지: 36 (크리티컬!)
입력 예시 2
공격력: 10
방어력: 15
크리티컬(1/0): 0
출력 예시 2
데미지: 1
힌트 1

규칙 세 줄을 순서대로 코드로 옮기면 돼요. 최소 데미지 처리를 크리티컬보다 먼저 해야 해요. 순서를 바꾸면 결과가 달라지는 입력이 있어요.

힌트 2

"(크리티컬!)"은 크리티컬일 때만 붙어요. 출력도 if로 나눠야 해요.

검사 받기

  • 예시 2개가 똑같이 나온다
  • 공격력 10, 방어력 15, 크리티컬 1을 넣으면 2가 나온다
검사 질문: 최소 데미지 처리와 크리티컬 처리의 순서를 바꾸면 위 세 번째 입력의 결과가 어떻게 되나요?
더 해 보기: 크리티컬 여부를 입력받지 말고 랜덤으로 정해 보세요. (20% 확률)

2상점 구매 판정조건문

보유 골드, 캐릭터 레벨, 살 아이템 번호를 입력받아 살 수 있는지 판정하세요.

번호아이템가격레벨 제한
1포션50없음
2강철 검3005 이상
3기사 갑옷50010 이상
  • 1~3이 아닌 번호면 없는 아이템
  • 레벨이 모자라면 레벨 부족 (레벨 N 이상)
  • 골드가 모자라면 골드 부족 (N골드 더 필요)
  • 둘 다 괜찮으면 구매 완료! 남은 골드: N
  • 레벨과 골드가 둘 다 모자라면 레벨 부족만 출력해요.
입력 예시 1
골드: 400
레벨: 7
아이템 번호: 2
출력 예시 1
구매 완료! 남은 골드: 100
입력 예시 2
골드: 400
레벨: 7
아이템 번호: 3
출력 예시 2
레벨 부족 (레벨 10 이상)
힌트 1

먼저 아이템 번호에 따라 가격과 레벨 제한을 변수에 정해 두세요. 그러면 레벨·골드 판정 코드는 아이템마다 따로 쓰지 않고 한 번만 쓰면 돼요. 번호로 나누는 부분은 switch가 잘 어울려요.

힌트 2

판정 순서가 곧 우선순위예요. 없는 아이템 → 레벨 → 골드 순서로 확인하면 "둘 다 모자라면 레벨 부족만" 규칙이 저절로 지켜져요.

힌트 3

"N골드 더 필요"의 N은 가격에서 보유 골드를 뺀 값이에요.

검사 받기

  • 예시 2개가 똑같이 나온다
  • 골드 200, 레벨 7, 아이템 2 → 골드 부족 (100골드 더 필요)
  • 골드 50, 레벨 1, 아이템 1 → 구매 완료! 남은 골드: 0
  • 아이템 번호 0, 4 → 없는 아이템
검사 질문: 골드가 가격과 딱 같을 때 살 수 있어야 하죠? 내 코드에서 그걸 정하는 비교 연산자는 무엇이고, 다른 걸 쓰면 어떻게 되나요?
더 해 보기: 레벨 20 이상이면 10% 할인해 주세요. 그리고 구매 완료 뒤에 "하나 더 살까요? (1/0)"를 물어서 1이면 남은 골드로 다시 판정해 보세요.

3HP 바반복문

HP(0~100)를 입력받아 막대로 그려 주세요. 10칸짜리 막대이고, HP 10마다 # 한 칸, 나머지는 -로 채워요.

  • 0~100이 아닌 값을 넣으면 다시 입력하세요를 출력하고 다시 입력받아요. 맞는 값이 들어올 때까지 반복해요.
  • HP가 30 이하면 막대 뒤에 위험!을 붙여요.
입력 예시 1
HP: 75
출력 예시 1
HP [#######---] 75
입력 예시 2
HP: 150
HP: 20
출력 예시 2
다시 입력하세요
HP [##--------] 20 위험!
힌트 1

# 개수는 HP를 10으로 나눈 몫이에요. - 개수는 10에서 # 개수를 뺀 거예요. 반복문 두 개로 그려요.

힌트 2

"맞는 값이 나올 때까지 입력받기"는 일단 한 번은 입력받아야 해요. 한 번은 무조건 실행하는 반복문이 있었죠?

검사 받기

  • 0, 9, 10, 100을 넣었을 때 막대가 모두 맞다
  • -5, 101을 넣으면 다시 입력받는다
검사 질문: HP가 9일 때 #은 몇 개인가요? 왜 그렇게 나오나요?
더 해 보기: 최대 HP도 입력받아서(예: 250 중 75), 비율로 10칸을 채워 보세요.

4업다운 게임반복문

컴퓨터가 1~100 사이의 숫자 하나를 랜덤으로 정해요. 사용자가 맞힐 때까지 숫자를 입력받고, 정답보다 작으면 UP, 크면 DOWN을 출력하세요.

  • 맞히면 몇 번 만에 맞혔는지 출력하고 끝내요.
  • 기회는 7번이에요. 7번 안에 못 맞히면 정답을 알려 주고 끝내요.
  • 실행할 때마다 정답이 달라야 해요.
실행 예시 1 (정답 63)
1번째: 50
UP
2번째: 75
DOWN
3번째: 63
정답! 3번 만에 맞혔어요
실행 예시 2 (정답 2)
1번째: 50
DOWN
...
7번째: 3
DOWN
실패! 정답은 2
힌트 1

1~100 랜덤은 랜덤 페이지의 "범위 정하기"를 보세요. 실행할 때마다 달라야 하니 씨앗(srand)도 필요해요.

힌트 2

반복이 끝나는 이유가 두 가지예요. 맞혔을 때, 7번을 다 썼을 때. 반복문 조건 하나로 쓰거나, 7번 반복하면서 맞히면 break 하는 방법이 있어요.

힌트 3

반복문이 끝난 뒤에는 "맞혀서 끝났는지, 기회를 다 써서 끝났는지" 구분해야 실패 메시지를 낼 수 있어요.

검사 받기

  • 두 번 실행했을 때 정답이 다르다
  • 7번째에 맞히면 "정답!"이 나오고 "실패!"는 안 나온다
  • 7번 다 틀리면 정답이 나온다
검사 질문: 1~100 사이의 숫자는 가장 잘 고르면 최대 몇 번 만에 맞힐 수 있나요? 그래서 기회가 7번인 이유는? (2진법 시간을 떠올려 보세요)
더 해 보기: 남은 범위를 알려 주세요. 예: UP (51 ~ 100)

5점수판배열 + 반복문

플레이어 5명의 점수를 배열에 입력받고 결과를 출력하세요.

  • 합계, 평균(소수점 첫째 자리까지), 최고 점수와 그 번호, 최저 점수와 그 번호를 출력해요.
  • 같은 점수가 여럿이면 앞 번호를 출력해요.
  • 마지막 줄에 평균 이상인 플레이어 번호를 모두 출력해요.
  • 점수는 0 이상이에요.
입력 예시 1
1번 점수: 80
2번 점수: 95
3번 점수: 70
4번 점수: 60
5번 점수: 100
출력 예시 1
합계: 405
평균: 81.0
최고: 100 (5번)
최저: 60 (4번)
평균 이상: 2번 5번
입력 예시 2
1번 점수: 50
2번 점수: 50
3번 점수: 50
4번 점수: 50
5번 점수: 51
출력 예시 2
합계: 251
평균: 50.2
최고: 51 (5번)
최저: 50 (1번)
평균 이상: 5번
힌트 1

입력, 합계, 최고·최저 찾기, 평균 이상 찾기를 반복문 여러 개로 나눠서 하나씩 만들어 봐요. 한 번에 다 하려고 하면 헷갈려요.

힌트 2

평균은 정수 ÷ 정수라서 소수점이 사라질 수 있어요. 예시 2의 50.2가 나오는지 꼭 확인해요.

힌트 3

최고 점수를 찾을 때 시작값을 무엇으로 할지 생각해 보세요. 0으로 시작해도 이 문제에서는 되지만, 더 안전한 시작값이 있어요. 그리고 번호도 같이 기억해야 해요.

검사 받기

  • 예시 2개가 똑같이 나온다 (특히 50.2)
  • 모두 같은 점수일 때 최고·최저 모두 1번이 나온다
  • 숫자 5가 코드 여러 곳에 흩어져 있지 않다
검사 질문: 최고 점수를 찾을 때 조건을 > 대신 >=로 쓰면 결과가 어떻게 달라지나요?
더 해 보기: 점수가 높은 순서대로 순위표를 출력해 보세요. (1위 5번 100점, 2위 2번 95점, ...)

!이럴 땐?

scanf_s 줄에 초록 물결 경고가 생겨요C6031: 반환 값이 무시되었습니다: 'scanf_s'.
왜?scanf_s가 "몇 개를 제대로 읽었는지" 돌려주는데 확인하지 않았다는 코드 분석 경고예요.
어떻게?이번 문제에서는 무시해도 실행에는 문제없어요. 빌드가 안 되는 에러와 헷갈리지 마세요.
숫자 대신 글자를 넣었더니 화면이 끝없이 올라가요다시 입력하세요 다시 입력하세요 다시 입력하세요 ...
왜?%d가 글자를 못 읽고 입력 창고에 그대로 남겨 둬요. 다음 반복에서도 같은 글자를 또 못 읽어요.
어떻게?이번 문제는 숫자만 넣는다고 생각하고 풀어요. Ctrl+C로 프로그램을 멈출 수 있어요.
업다운 정답이 실행할 때마다 똑같아요항상 42가 정답
왜?씨앗(srand)을 안 넣었거나, 반복문 안에 넣었어요.
어떻게?랜덤 페이지를 다시 보세요. srand는 프로그램 시작할 때 한 번만.
평균이 50.0이나 0.000000으로 나와요평균: 50.0 (기대: 50.2)
왜?int ÷ int는 몫만 남아요. 그걸 실수 변수에 넣어도 이미 소수점은 사라진 뒤예요. int를 %f로 찍으면 0.000000 같은 엉뚱한 값이 나와요.
어떻게?나누기 전에 한쪽을 실수로 바꿔요. 연산자 페이지의 "정수 나누기"를 다시 보세요.
배열 마지막 값이 이상하거나 끝날 때 오류 창이 떠요Run-Time Check Failure #2 - Stack around the variable 'score' was corrupted.
왜?칸이 5개면 번호는 0~4예요. 반복 조건이 <= 5라서 5번 칸(없는 칸)에 썼어요.
어떻게?반복 조건을 확인해요. 화면에는 1번~5번으로 보여 주고, 배열은 0~4를 쓰는 것에 주의해요.

에러 번호와 문구는 Visual Studio 기준이에요. 파일 종류(.c/.cpp)와 버전에 따라 조금 다를 수 있어요.
