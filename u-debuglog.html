printf와 Debug.Log유니티의 printf

C에서 값을 확인할 땐 printf를 썼어요. 유니티에서는 Debug.Log를 써요. 결과는 검은 콘솔 창이 아니라 유니티 에디터의 Console 창에 나와요.

Cprintf("HP: %d\n", hp);
HP: 100
유니티Debug.Log("HP: " + hp);
ⓘ HP: 100

1Debug.Log란?

유니티 Console 창에 메시지를 찍는 함수예요.Debug = 벌레(버그) 잡기, Log = 기록

printf와 하는 일은 같아요. 값이 내 생각대로 들어 있는지 확인하는 거예요. 다른 점은 누가 보느냐예요.

printf (C)Debug.Log (유니티)
어디에 나와?검은 콘솔 창유니티 에디터의 Console 창
누가 봐?사용자도 봐요 (콘솔 게임의 화면 그 자체)개발자만 봐요. 게임 플레이어는 못 봐요
줄바꿈\n을 직접한 번 부를 때마다 자동으로 한 줄
값 넣기%d, %f 같은 서식+로 이어 붙이기, 또는 $"{hp}"

2왜 printf가 아니야?

검은 창이 없어요유니티 게임은 그림으로 된 화면이라 글자를 찍을 콘솔 창이 없어요. 게임 화면에 글자를 보이려면 UI를 써요.
어디서 찍었는지 알려 줘요Console의 줄을 두 번 클릭하면 그 Debug.Log를 쓴 코드 줄로 바로 이동해요.
C#엔 printf가 없어요C#은 C와 다른 언어라 함수 이름도 달라요. 유니티에서는 Debug.Log가 기본이에요.

3바꿔 쓰기

C (printf)C# (Debug.Log)
printf("안녕\n");Debug.Log("안녕");
printf("HP: %d\n", hp);Debug.Log("HP: " + hp);
printf("%d / %d\n", hp, maxHp);Debug.Log(hp + " / " + maxHp);
printf("%s Lv.%d\n", name, lv);Debug.Log($"{name} Lv.{lv}");
printf("%.1f\n", speed);Debug.Log(speed.ToString("F1"));

$"…" 문자열 (보간 문자열)

string name = "용사";
int lv = 3;
Debug.Log($"{name} Lv.{lv}");      // 용사 Lv.3

따옴표 앞에 $를 붙이면 { } 안에 변수를 바로 쓸 수 있어요. printf의 %d 자리에 변수 이름을 직접 쓰는 느낌이에요.

예제

Start에서 값 확인하기

using UnityEngine;                  // Debug를 쓰려면 꼭 필요

public class Player : MonoBehaviour
{
    int hp = 100;
    float speed = 3.5f;

    void Start()
    {
        Debug.Log("HP: " + hp);           // HP: 100
        Debug.Log($"속도: {speed}");       // 속도: 3.5
        if (hp < 30)
            Debug.LogWarning("HP가 너무 낮아요");
    }
}

6문제 풀기

  
1번결과 맞히기
Debug.Log("HP: " + 10 + 5);

    
정답 보기
HP: 105예요. 왼쪽부터 붙여요. "HP: " + 10 → "HP: 10", 거기에 + 5 → "HP: 105". 글자 뒤에 붙는 숫자는 글자로 이어 붙여져요.
많이 틀리는 답: HP: 15

  
2번결과 맞히기
Debug.Log(10 + 5 + " HP");

    
정답 보기
15 HP예요. 왼쪽부터 10 + 5 = 15(숫자끼리 더하기), 그다음 " HP"를 붙여요. 1번과 순서만 다른데 결과가 달라요. 헷갈리면 "HP: " + (10 + 5)처럼 괄호를 쳐요.

  
3번바꿔 쓰기
printf("%s의 레벨은 %d\n", name, level);
Debug.Log로 바꿔 보세요.

    
정답 보기
Debug.Log(name + "의 레벨은 " + level);
// 또는
Debug.Log($"{name}의 레벨은 {level}");
\n은 필요 없어요.

  
4번고쳐 보기
Debug.Log("HP: %d", hp);
빨간 에러가 나요. 왜일까요?

    
정답 보기
Debug.Log는 %d 서식을 모르고, 두 번째 칸에는 유니티 오브젝트만 넣을 수 있어요. Debug.Log("HP: " + hp);로 고쳐요.

  
5번도전
게임을 빌드해서 친구에게 줬어요. 친구 화면에 Debug.Log 내용이 보일까요? 점수를 친구에게 보여 주려면?

    
정답 보기
안 보여요. Debug.Log는 개발자용 기록이에요. 플레이어에게 보여 줄 글자는 UI (Canvas의 Text)로 화면에 띄워요.






  
7이럴 땐?

  
printf를 썼더니 에러error CS0103: The name 'printf' does not exist in the current context

    
왜?C#에는 printf가 없어요.

      
어떻게?Debug.Log("…");로 바꿔요.

  
Debug.log라고 썼더니 에러error CS0117: 'Debug' does not contain a definition for 'log'

    
왜?C#은 대소문자를 구분해요. log가 아니라 Log예요.

      
어떻게?Debug.Log로 고쳐요. 자동 완성(Tab)을 쓰면 안 틀려요.

  
Debug를 모른대요error CS0103: The name 'Debug' does not exist in the current context

    
왜?파일 맨 위의 using UnityEngine;이 빠졌어요. C의 #include <stdio.h>를 빼먹은 것과 같아요.

      
어떻게?맨 위에 using UnityEngine;을 써요.

  
Debug가 두 개래요error CS0104: 'Debug' is an ambiguous reference between 'UnityEngine.Debug' and 'System.Diagnostics.Debug'

    
왜?Visual Studio가 자동으로 using System.Diagnostics;를 넣었어요. 같은 이름 Debug가 두 개라 헷갈려요.

      
어떻게?맨 위의 using System.Diagnostics; 줄을 지워요.

  
printf처럼 %d를 썼어요error CS1503: Argument 2: cannot convert from 'int' to 'UnityEngine.Object'

    
왜?Debug.Log("HP: %d", hp). 두 번째 칸은 "어느 오브젝트의 로그인지" 적는 자리라 숫자를 못 받아요.

      
어떻게?+로 붙이거나 $"HP: {hp}"를 써요.

  
Console 창에 아무것도 안 나와요 (에러 없음)Console이 비어 있음

    
왜?① Console 오른쪽 위 말풍선 필터가 꺼졌거나 ② 스크립트가 오브젝트에 안 붙었거나 ③ 그 줄까지 코드가 안 왔어요(if 조건 등).

      
어떻게?필터 아이콘 3개가 모두 눌려 있는지 봐요. 스크립트가 붙어 있는지 Inspector에서 봐요.

  
로그가 수천 줄 쌓여서 에디터가 느려요ⓘ 999+

    
왜?Update 안에 Debug.Log가 있어서 프레임마다 찍혀요.

      
어떻게?확인이 끝난 Debug.Log는 지워요. 잠깐 볼 땐 Collapse를 켜요.

  
에러 문구는 Unity 6 + Visual Studio 기준이에요. 버전에 따라 조금 다를 수 있어요.
