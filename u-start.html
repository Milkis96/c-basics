Start와 main유니티에는 main이 없어요

C에서는 프로그램이 main에서 시작했어요. 유니티에서는 우리가 main을 쓰지 않아요. 대신 오브젝트가 게임에 등장할 때 유니티가 Start를 불러 줘요.

유니티
Play→Start() 오브젝트마다 한 번→Update() 매 프레임

1Start란?

오브젝트가 게임에 처음 등장할 때 유니티가 딱 한 번 불러 주는 함수예요.첫 프레임이 그려지기 직전에 불려요

C의 main은 프로그램 전체의 시작점이라 딱 하나만 있었어요. 유니티의 Start는 스크립트를 붙인 오브젝트마다 하나씩 있어요. 플레이어에도, 적에도, 아이템에도 각자의 Start가 있어요.

그리고 우리가 main을 부른 적이 없듯이, Start도 우리가 부르지 않아요. 이름만 정확히 Start로 써 두면 유니티가 알아서 불러요.

2왜 main이 없어?

main은 유니티가 갖고 있어요유니티 엔진도 C++로 만든 프로그램이라 main이 있어요. 엔진의 main이 돌면서 우리 스크립트를 불러 줘요.
게임 루프도 엔진이 돌려요C로 게임을 만들 땐 while(1)을 직접 썼어요. 유니티는 이 반복을 대신 돌리고, 한 바퀴마다 우리 Update를 불러요.
오브젝트마다 준비가 달라요플레이어는 HP를 100으로, 적은 50으로. 각자 자기 Start에서 자기 준비를 해요.

3코드로 비교

C

main 하나에 준비 + 게임 루프

int main(void) {
    int hp = 100;                  // 준비: 한 번
    printf("시작! HP: %d\n", hp);

    while (1) {                    // 게임 루프: 계속
        // 입력 받기, 움직이기, 그리기
    }
}
유니티

준비는 Start, 반복은 Update

using UnityEngine;

public class Player : MonoBehaviour
{
    int hp;

    void Start()                   // 준비: 한 번 (main 윗부분)
    {
        hp = 100;
        Debug.Log("시작! HP: " + hp);
    }

    void Update()                  // 매 프레임 (while 안쪽)
    {
        // 입력 받기, 움직이기
    }
}

4유니티가 부르는 함수들

Start처럼 유니티가 정해진 때에 불러 주는 함수를 이벤트 함수라고 해요. 이름과 대소문자가 정확해야 불려요.

함수언제 불려?주로 하는 일
Awake()오브젝트가 만들어지자마자, 한 번내 것 준비 (GetComponent 등)
Start()첫 Update 직전, 한 번 (스크립트가 켜져 있을 때만)다른 오브젝트를 쓰는 준비
Update()매 프레임 (1초에 수십 번)입력, 이동
FixedUpdate()일정한 간격 (기본 0.02초)물리 (Rigidbody)
OnDestroy()오브젝트가 없어질 때정리

순서 한 줄 요약

Awake → Start → Update → Update → Update … 오브젝트가 여러 개면 모두의 Awake가 먼저 끝나고, 그다음 Start들이 불려요. 하지만 Player의 Start와 Enemy의 Start 중 누가 먼저일지는 정해져 있지 않아요.

5직접 해 보기

두 오브젝트에 같은 스크립트를 붙였어요. ▶ Play를 누르고 프레임을 넘겨 보세요. Enemy의 체크를 끄고 다시 해 보세요.

void Awake()  { Debug.Log(name + " Awake"); }
void Start()  { Debug.Log(name + " Start"); }
void Update() { Debug.Log(name + " Update"); }

Enemy
정지 상태

체크를 끈 스크립트는 Awake만 불리고, Start와 Update는 안 불려요. 게임 도중에 체크를 다시 켜면 그 다음 프레임에 Start가 한 번 불린 뒤 Update가 시작돼요.

6문제 풀기

1번개수 맞히기

Start에 Debug.Log("시작!");이 있는 스크립트를 오브젝트 3개에 붙였어요. Play를 누르면 "시작!"은 몇 번 찍힐까요?

정답 보기

3번이에요. Start는 스크립트가 붙은 오브젝트마다 하나씩 불려요.

많이 틀리는 답: 1번 (main처럼 하나뿐이라고 생각해서)
2번개수 맞히기

Update에 Debug.Log("a");를 넣고 게임을 2초 동안 돌렸어요. 1초에 60프레임이라면 "a"는 대략 몇 번 찍힐까요?

정답 보기

약 120번이에요. Update는 프레임마다 불려요. 컴퓨터 성능에 따라 프레임 수가 달라서 "대략"이에요.

3번결과 맞히기
void Start()  { Debug.Log("S"); }
void Update() { Debug.Log("U"); }

Console에 처음 네 줄은?

정답 보기

S U U U예요. Start가 먼저 한 번, 그 뒤로 Update가 계속이에요.

4번고쳐 보기
void start()
{
    Debug.Log("시작!");
}

에러는 없는데 아무것도 안 찍혀요. 왜일까요?

정답 보기

소문자 start라서 유니티가 못 알아봐요. 유니티는 정확히 Start라는 이름만 불러요. C#은 대소문자를 구분해요.

5번도전

C 습관대로 Start 안에 while (true) { … } 게임 루프를 넣으면 어떻게 될까요?

정답 보기

유니티가 멈춰요(응답 없음). 유니티는 Start가 끝나야 다음 일(Update, 화면 그리기)을 할 수 있는데, Start가 영원히 안 끝나요. 반복은 Update에게 맡겨요.

7이럴 땐?

Start에 쓴 Debug.Log가 안 나와요 (에러 없음)Console 창이 비어 있음
왜?① 스크립트를 오브젝트에 안 붙였거나 ② 이름이 start처럼 틀렸거나 ③ Inspector에서 스크립트 체크가 꺼져 있거나 ④ Console의 로그 필터(말풍선 아이콘)가 꺼져 있어요.
어떻게?Hierarchy에서 오브젝트를 누르고 Inspector에 스크립트가 붙어 있는지, 체크가 켜져 있는지 봐요.
스크립트를 오브젝트에 붙일 수 없어요Can't add script component 'Player' because the script class cannot be found. Make sure that there are no compile errors and that the file name and class name match.
왜?파일 이름(Player.cs)과 public class Player의 이름이 다르거나, 프로젝트 어딘가에 빨간 컴파일 에러가 남아 있어요.
어떻게?두 이름을 똑같이 맞춰요(대소문자까지). Console의 빨간 에러를 먼저 모두 고쳐요.
Play를 누르자마자 유니티가 멈춰요Unity (응답 없음)
왜?Start나 Update 안에 끝나지 않는 while이 있어요.
어떻게?작업 관리자로 끄는 수밖에 없어서 저장 안 한 씬이 날아가요. 반복 처리는 Update에서 프레임마다 조금씩 해요. Play 전에 Ctrl+S 습관!
Start에서 다른 오브젝트 값을 쓰면 가끔 에러가 나요NullReferenceException: Object reference not set to an instance of an object
왜?상대 오브젝트의 Start가 아직 안 불려서 준비가 안 됐어요. Start끼리는 순서가 정해져 있지 않아요.
어떻게?내 것 준비는 Awake, 남의 것 사용은 Start로 나눠요. Awake는 모든 Start보다 먼저 끝나요.
main 함수를 만들었는데 안 불려요static void Main() { … } // 아무 일도 안 일어남
왜?유니티는 우리 스크립트의 Main을 부르지 않아요. 엔진의 main이 따로 있어요.
어떻게?시작할 때 할 일은 Start에 써요.
